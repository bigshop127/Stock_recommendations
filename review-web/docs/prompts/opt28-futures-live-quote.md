# 優化專案 28 — 期貨即時報價（期交所 MIS 盤中／夜盤），取代「永遠慢一個交易日」的每日行情檔

> 互動模式（沿用全案）：Claude 給規格＋驗收標準；**你寫 code**，寫完 Claude review。
> 開工方式：開新對話「請你幫我去閱讀 `review-web\docs\prompts\opt28-futures-live-quote.md`，然後根據裡面的說明進行」。
> **相依**：opt23／opt25／opt27 已完工。本案是 opt27（加權指數自動同步）在期貨價格上的對應版本，**做法刻意抄 opt27**。
> **範圍**：🟡 gateway 改一支既有端點 ＋ 前端取價順序與狀態列。零 engine 改動、零新依賴、零新資料表。

## 0. 為什麼要做

使用者 2026-08-04 的原話：「為什麼我按真實同步它沒辦法自動去抓小型 0050 期貨最新的價格」。

**它有抓到，只是資料源本身就只更新到上一個交易日。**

`routes/futures.js` 的 `/api/futures/quote` 走期交所 OpenAPI `DailyMarketReportFut`，那是**收盤後才產出的每日行情檔**。2026-08-04 22:06 實測，SRF 回的是：

```
Date: 20260803   ContractMonth: 202608   SettlementPrice: 101.65
```

也就是說 8/4 整天不管按幾次「真實同步」，拿到的都是 **8/3 的結算價**。而且期交所的每日檔要等**當天夜盤（跑到隔天 05:00）結束**才會產出，所以 8/4 的檔案要 8/5 早上才出現——**盤中永遠落後一個交易日，這不是快取問題也不是 bug，是資料源的性質**。

同一時間的真實價格（下表全是 2026-08-04 實測）：

| | SRF 202608 |
|---|---|
| 頁面現在顯示（＝8/3 結算價） | 101.65 |
| 8/4 日盤收盤 | **100.95** |
| 8/4 夜盤現價（22:14） | **102.80** |

**為什麼這件事值得做**：這頁的權益數、未實現損益、風險指標、壓力測試全部吃現價。差 1.85 元 ＝ 一口 1,000 股 ＝ **每口 1,850 元**的權益數誤差；八口就是 14,800。風險指標的分母（維持保證金）是對的、分子是錯的，於是「離追繳還有多遠」會安靜地算錯——**和 opt25 保證金抓錯是同一類故障：不會報錯，只會讓危險數字看起來比較安全**。

> 追繳價／斷頭價**本身不受影響**（那是由保證金反解出來的價格門檻，與當下現價無關）。受影響的是「現在離那個門檻多遠」。

## 1. 資料源調查結論（**已查證，不用重查**）

Claude 已於 2026-08-04 實測，以下全部是實跑出來的結果。

### 1.1 端點

```
POST https://mis.taifex.com.tw/futures/api/getQuoteDetail
Content-Type: application/json

{"SymbolID": ["SRFH6-F", "SRFH6-M", ...]}
```

- 這是**期交所自己的行情看板（mis.taifex.com.tw）在用的端點**，與 opt27 用的 TWSE MIS 是同一類東西、同一個立場（官方公開端點，不是爬他站策展內容）。
- **公開、免金鑰**。實測 **不需要** `Referer`／`Origin`／`User-Agent`，只給 `Content-Type` 就會回。
  > ⚠️ 這點與 opt27 的 TWSE MIS **相反**（那邊少了 `Referer` 會被擋回 rtcode 5001）。仍建議照送 `Referer: https://mis.taifex.com.tw/futures/` 與 `User-Agent`，成本是零、對方哪天開始檢查也不會壞。
- **只吃 POST**，GET 回 405。
- **可以一次批次多個 SymbolID**（實測一次 7 個 OK），所以「所有到期月份 × 兩個時段」用**一個 request** 就拿得完，不要迴圈逐月打。
- 回應：`{"RtCode":"0","RtMsg":"","RtData":{"QuoteList":[...]}}`。`RtCode !== "0"` 視為失敗。
  > ⚠️ **查不到的 SymbolID 不會報錯**，而是回一筆**所有欄位都是空字串**的元素（連 `SymbolID` 都是 `""`）。所以不能靠陣列長度對位，**要用回應裡的 `SymbolID` 反查**，對不到就當作沒有這個月份。

### 1.2 SymbolID 的組法（**這是本案最容易踩的地方**）

格式：`{MIS商品代碼}{月碼}{年尾數}-{時段}`

**① 月碼＝A–L 對應 1–12 月**（實測驗證四組：`H6`=202608、`I6`=202609、`L6`=202612、`C7`=202703、`F7`=202706）

**② 年＝西元年最後一位數**（2026 → `6`）

**③ MIS 的商品代碼和 OpenAPI 的不是同一套**——這是必須做對照表的原因，實測五個 preset 全部驗證過：

| 頁面 preset（`SYMBOL_PRESETS.code`，＝OpenAPI `Contract`） | MIS 代碼 | 實測回應的 `DispCName` |
|---|---|---|
| `SRF` | `SRF` | 小型元大台灣50ETF期貨086 |
| `NYF` | `NYF` | 元大台灣50ETF期貨086 |
| `TX` | **`TXF`** | 臺指期086 |
| `MTX` | **`MXF`** | 小臺指期086 |
| `TMF` | `TMF` | 微臺指期086 |

> `MXFH6-F` 有值、`MTXH6-F` 回空——**代碼直接沿用 OpenAPI 那套會靜默拿不到台指期的即時價**。對照表對不到的自訂代碼（使用者可自填 `contract`）就**不打 MIS，直接走每日檔**，不要猜。

**④ 時段後綴**

| 後綴 | 意義 | 交易時間（台北） |
|---|---|---|
| `-F` | 一般交易時段（日盤） | 08:45–13:45 |
| `-M` | 盤後交易時段（夜盤） | 15:00–翌日 05:00 |

實測 22:14 時 `-M` 是活的（`CTime: 221447`、`CTotalVolume: 3914`），`-F` 停在當天 `134458`。**股票／ETF 類期貨（SRF／NYF）也有夜盤**，不是只有台指期有。

### 1.3 欄位

實測樣本（2026-08-04 22:14）：

```jsonc
{ "SymbolID":"SRFH6-F", "Status":"TC", "DispCName":"小型元大台灣50ETF期貨086",
  "CLastPrice":"100.95", "CRefPrice":"101.65",     // CRefPrice ＝ 前一時段的參考價（昨結算／日盤收盤）
  "COpenPrice":"100.30", "CHighPrice":"102.20", "CLowPrice":"99.80",
  "CTotalVolume":"16356", "OpenInterest":"15815",
  "CBestBidPrice":"100.95", "CBestAskPrice":"101.00",
  "CDate":"20260804", "CTime":"134458" }              // CTime ＝ HHMMSS
```

要用的只有：`SymbolID`／`CLastPrice`／`CRefPrice`／`CTotalVolume`／`CBestBidPrice`／`CBestAskPrice`／`CDate`／`CTime`。

> ⚠️ **`CLastPrice` 在沒有成交的月份是 `"0.00"` 或空字串，`CTime` 同時是空的**（實測 `SRFF7-F`：`last:"0.00" vol:"0" time:""`）。**`0` 不是價格**——直接吃下去會讓那個月份的部位權益數變成 0，比沒抓到還糟。判定條件是 `parseFloat > 0` **且** `CTime` 非空。
>
> ⚠️ **不要拿 `CRefPrice` 當現價**。它是參考價（`-F` 的是昨日結算價、`-M` 的是當天日盤收盤價），拿它當現價等於原地繞回本案要解決的那個問題。它只適合拿來算漲跌幅或當佐證。
>
> ⚠️ **`Status` 欄位語意未確認**（日盤收盤後是 `"TC"`、夜盤進行中是 `""`）。**不要拿它做任何判斷**，用 `CDate`／`CTime` 與時鐘就夠了。

### 1.4 沒有月份清單端點

探測過 `getCmdyInfo`／`getContractInfo`／`getDderivativesList` 皆 404。`getQuoteList` 存在但**一次回 19,729 筆全市場報價**，為了拿五個月份去拉它不划算。

**所以到期月份清單仍然由既有的 `DailyMarketReportFut` 提供**（它本來就已經在解析了），MIS 只負責把價格覆蓋上去。這也順便決定了本案的架構——見 §2。

## 2. 後端：改造 `GET /api/futures/quote`（`routes/futures.js`）

### 2.1 架構＝「每日檔給骨架，MIS 給即時價」

**不要另開一支端點，也不要拿 MIS 取代每日檔。** 兩者各有不可取代的部分：

| | `DailyMarketReportFut`（既有） | MIS `getQuoteDetail`（新增） |
|---|---|---|
| 有哪些到期月份 | ✅ 唯一來源 | ❌ 要自己組 SymbolID |
| 結算價 | ✅ | ❌ |
| 即時／當日價 | ❌ 慢一個交易日 | ✅ |
| 未成交的遠月 | ✅ 仍有結算價 | ❌ 只有 0 |

流程：

1. 照現行邏輯抓每日檔 → `parseRows()` 得到月份清單（**這段一行都不用改**）
2. 用 `contract` 查 MIS 代碼對照表；**對不到就跳過第 3–4 步**（回應形狀不變，只是沒有 live 欄位）
3. 把每個月份組成 `-F` 與 `-M` 兩個 SymbolID，**一次 POST 打完**
4. 逐月份挑出「該用哪個時段的價」（§2.2），覆蓋進回應

**MIS 這一段整段包在 try/catch 裡：失敗就當作沒有即時價，靜靜退回每日檔的結果。** 理由＝MIS 掛掉時「慢一天的價格」仍然遠比「整個端點 502、頁面一個數字都沒有」有用。但前端要看得出來現在是哪一種（§3.2）。

### 2.2 挑時段的規則

用**台北時間的時鐘**判斷，不要靠 `Status` 欄位：

```
08:45 ≤ t < 15:00  →  優先 -F（日盤進行中，或 13:45–15:00 的空檔仍以當天日盤收盤為最新）
其餘時間           →  優先 -M（夜盤進行中，或夜盤剛結束、其收盤比日盤晚）
```

選中的那個**沒有有效價**（§1.3 的判定）時，**退到另一個時段**；兩個都沒有才放棄該月份、留給每日檔的結算價。

時區照抄 `routes/market.js` 的 `isTaiexSession()` 做法——**VM 跑在 UTC，自己加 8 小時，不要依賴系統時區**。週末／國定假日不需要特別判斷：兩個板子上都是最後一次交易的資料，取到的價格仍然正確，只是不會被標成即時（§2.3）。

> 🔍 **有一件事請你在實作時順手驗證，並把結論寫進程式註解**：夜盤跨過午夜之後（例如台北時間 02:00），`-M` 回的 `CDate` 是**當天**（20260805）還是**開盤那天**（20260804）？22:14 實測時是 `20260804`，午夜後沒測到。這隻影響「報價時間」怎麼顯示，不影響取價（時鐘規則已經先決定了時段），所以**不是擋路的問題**，但註解裡要寫清楚，別讓下一個人以為驗證過了。

### 2.3 回應形狀（**只新增欄位，既有欄位語意完全不動**）

`months[]` 的每一筆加上：

```jsonc
{
  "month": "202608",
  "settlement": 101.65,        // 既有，來自每日檔，語意不變
  "last": 101.65,              // 既有，來自每日檔（該日收盤），語意不變
  "...": "其餘既有欄位不動",

  "live": 102.80,              // 新增：即時價；沒有就 null
  "live_session": "night",     // 新增：'day' | 'night' | null
  "live_time": "2026-08-04T22:14:47+08:00",  // 新增：CDate + CTime 組出來
  "live_volume": 3914,         // 新增：該時段累計成交量（判斷這個月份有沒有人在交易）
  "live_bid": 102.80,          // 新增：委買一（可選，做價差顯示用）
  "live_ask": 102.85           // 新增：委賣一（可選）
}
```

頂層加上：

```jsonc
{
  "date": "2026-08-03",        // 既有：每日檔的資料日，語意不變
  "live_source": "taifex-mis",  // 新增；MIS 沒抓到時是 null
  "live_as_of": "2026-08-04T22:14:47+08:00",   // 新增：所有月份裡最新的那個報價時間
  "intraday": true,             // 新增：見下
  "live_error": null            // 新增：MIS 失敗時放原因字串，成功時 null
}
```

**`intraday` 的定義**：`現在時間 − live_as_of < 5 分鐘`。

刻意**不用「現在是不是交易時段」來判定**——國定假日一樣落在 08:45–13:45 裡，用時段判會在休市日謊報「即時」。用「報價時間有多新」則是自我修正的：休市日最後一筆是幾天前，自然標成非即時。這比 opt27 的 TAIEX 版更嚴謹一點，是刻意的。

### 2.4 快取

現行 `QUOTE_TTL_MS = 10 分鐘` 是配合「每日行情一天只變一次」訂的，**接了即時價之後這個 TTL 會讓即時價變成最多 10 分鐘前的價**——那就白做了。

改成兩段：

```js
const QUOTE_TTL_LIVE_MS   = 20 * 1000;       // 有即時價時（intraday）：20 秒，比照 opt27 的 30 秒
const QUOTE_TTL_CLOSED_MS = 10 * 60 * 1000;  // 非交易時段：維持 10 分鐘
```

**每日檔與 MIS 分開快取**：每日檔 TTL 維持 10 分鐘（它本來就一天才變一次，沒必要每 20 秒重抓 815 KB），只有 MIS 那段跟著 20 秒的節奏走。這樣按「真實同步」的成本是一個小 JSON 請求而不是一次 815 KB 下載。

⚠️ 沿用 opt25／opt27 的快取鐵律：**`cached` / `stale` / `intraday` 是「這次回應」的性質，不是資料的性質**——不要落地、不要寫死進快取物件，旗標要跟著記憶體快取一起帶出去，每次回應時重算。

## 3. 前端

### 3.1 取價順序（`FuturesPnl.tsx` 的 `fetchQuote`）

現行：

```ts
const p = m.settlement ?? m.last ?? 0;
```

改成：

```ts
const p = m.live ?? m.settlement ?? m.last ?? 0;
```

其餘（`prices` 逐月存、`referenceMonthOf` 挑參考月份、`price` / `price_month` / `price_as_of` 回填）**完全不動**。

`price_as_of` 目前只存日期字串，改成能表達「哪一天的什麼時間、哪個時段」——建議直接存 `live_as_of`（有即時價時）或維持 `date`（沒有時），並在 `FuturesConfig` 加一個 `price_source: 'live' | 'daily'`。**這個欄位要一路存進雲端 `data/futures_positions.json`**，因為告警腳本（§4）也要判斷。

> ⚠️ `futuresStore.ts` 的 `normalizeFutures()` 要補上新欄位的預設值（舊的雲端 JSON 沒有這兩個欄位）。**localStorage KEY 維持 `review:futures:v1` 不要改版號**——加欄位而已，改版號會把使用者現有的部位設定清掉。

### 3.2 狀態列要說得出「這個價是什麼時候的」

現在標題卡下方那條狀態列只寫「期交所行情 2026-08-03（2026/08 月份）」，看不出那是**上一個交易日的結算價**。比照 opt27 的加權指數那段（同一條狀態列上就有現成範例）改成：

| 情況 | 文案 |
|---|---|
| 日盤即時 | `期交所報價 102.80（日盤即時 13:44:58）` |
| 夜盤即時 | `期交所報價 102.80（夜盤即時 22:14:47）` |
| 剛收盤／非交易時段 | `期交所報價 100.95（2026-08-04 日盤收盤）` |
| MIS 掛掉、退每日檔 | `期交所報價 101.65（2026-08-03 結算價，即時報價暫時失效）` ← 用 amber 色 |

**最後一列是本案最重要的一行文案**。整個 opt28 就是為了解決「數字看起來像最新的、其實是上一個交易日的」，所以退回每日檔的時候一定要**當面講出來**，不能靜靜地顯示一個看不出年紀的數字。

「持倉月份的現價」那排（`FuturesPnl.tsx:1426` 附近）同理：現在只有「沒行情就標黃字『參考價』」，再加一種狀態——**該月份有結算價但沒有即時價**（遠月常態，例如 202706 今天完全沒成交）時標一個灰字「結算價」，`title` 寫明是哪一天的。

### 3.3 「整體邏輯」分頁要更新

那頁現在寫著「真實同步＝抓期交所**每日**行情」。改成講清楚兩個來源怎麼接力（日盤／夜盤 MIS 即時 → 退每日檔結算價），以及**遠月沒成交時只有結算價**是正常的、不是壞掉。

### 3.4 順手修掉「參考價」欄位造成的誤會（小改動，但這就是使用者最初問的問題）

使用者 2026-08-04 看著設定卡問「**參考價（沒有行情的月份用這個）是什麼？**」。它的實際語意是 `priceOf()` 的 fallback：某個到期月份在期交所沒有價時才會用到。但現在的呈現有兩個問題：

1. 它被放在「帳戶」卡最上面、和保證金專戶餘額並排，看起來像是主要的價格輸入。
2. 「真實同步」會**自動把它覆寫成參考月份的價格**，於是它總是等於下面那排月份現價的其中一個——使用者看到兩個一樣的數字，完全看不出它是退路。

改動（都只是呈現，零算式變更）：

- 標籤改成 **「後備價（只有抓不到行情的月份會用到）」**
- 在欄位下方顯示一行動態狀態：
  - 目前**沒有**任何持倉月份在用它 → 灰字「目前所有持倉月份都有行情，這格沒有被使用」
  - 有月份在用它 → amber 字「2027/06 正在用這格計價」
- 位置從「帳戶」卡移到「持倉月份的現價」那排的**下方**（它服務的是那排，不是保證金餘額）

## 4. 選配：告警腳本一併吃即時價（建議做）

`scripts/futures_alert.cjs` 目前打 `/api/futures/quote` 取價。端點升級後它會自動吃到即時價，**但有一個副作用要處理**：那支腳本會寫每日權益快照，而 opt24 明訂「**只有拿到當日真行情才寫**，免得把舊價寫成新的一天」。

現在判斷「是不是當日行情」的依據是每日檔的 `date`，升級後要改看新的 `live_as_of`／`intraday`：

- cron 掛在 15:05（日盤收盤後、夜盤剛開始），此時 `-F` 的收盤價就是當日正確的收盤，`intraday` 會是 false（超過 5 分鐘）——**所以不能用 `intraday === true` 當寫入條件**，要用「`live_as_of` 的日期 ＝ 今天」。
- MIS 掛掉退回每日檔時，`date` 會是昨天 → **照舊跳過不寫**，行為不變。

> 這一條沒處理的話，會出現「權益曲線上多一個用昨天價格算出來的今天」的髒資料，而且是**寫進歷史檔、事後看不出來**的那種。所以雖然標「選配」，實際上比 §3 的文案更該優先做。

## 5. 測試與驗收

### 5.1 後端手動驗收

```powershell
curl "http://localhost:3000/api/futures/quote?contract=SRF"
```

分別在四個時間點各打一次，核對 `live_session` / `intraday` / 價格：

| 時間（台北） | 預期 |
|---|---|
| 10:00（盤中） | `live_session:"day"`、`intraday:true`、價格隨時間變動 |
| 14:00（日盤已收、夜盤未開） | `live_session:"day"`、`intraday:false`、價格＝當日日盤收盤 |
| 21:00（夜盤中） | `live_session:"night"`、`intraday:true` |
| 週末 | `intraday:false`、價格＝上週五夜盤收盤，且**不報錯** |

其他必驗：

- `contract=TX` → 要能拿到即時價（驗證 `TX → TXF` 對照表；這是最容易漏的一條）
- `contract=XYZ`（對照表沒有的自訂代碼）→ 回應形狀正常、`live` 全 null、**不是錯誤**
- 把 MIS URL 改壞（比照 `TAIFEX_MARGINS_URL` 加一個 `TAIFEX_MIS_URL` 環境變數覆寫）→ 端點仍回 200、`live_error` 有值、每日檔的價格照常回
- 遠月（例如 202706）→ `live: null`，`settlement` 仍在

**數值合理性核對（沿用 opt14／opt25 的教訓：HTTP 200 不等於數字對）**：拿 `live` 去和期交所看盤網頁 `https://mis.taifex.com.tw/futures/` 上同一個月份的畫面**目視對一次**。差一檔（0.05）是時間差，差一元以上就是解析錯了。

### 5.2 前端

- 盤中按「真實同步」→ 權益數／未實現損益／風險指標**要跟著動**（這是本案的驗收核心：連按兩次間隔一分鐘，數字應該不一樣）
- MIS 失敗時，頁面要顯示 amber 的「即時報價暫時失效」而**不是**安靜地顯示舊價
- 遠月部位顯示「結算價」灰字標記
- 「後備價」欄位的使用中／未使用狀態文案正確

### 5.3 自動測試

MIS 解析是純資料轉換，**請把 §1.3 的實測 JSON 存成 fixture 寫單元測試**，至少涵蓋：

- `CLastPrice: "0.00"` 且 `CTime: ""` → 判為無效，不進 `live`（**這一條最重要**）
- `CLastPrice: ""` → 同上
- 查不到的 SymbolID 回空字串元素 → 不會對位到別的月份
- `SRFH6` ↔ `202608`、`SRFC7` ↔ `202703` 的月碼雙向轉換
- `TX → TXF`、`MTX → MXF`、對照表沒有的代碼 → null

`npm run build`（**不是只跑 `tsc --noEmit`**，VM 的 build 用 `tsc -b` 比較嚴格，這個坑 opt19 踩過）與 `npx vitest run` 全綠。

## 7. 不做／備註

- ❌ **不改追繳價／斷頭價的公式**。那是保證金反解出來的價格門檻，與當下現價無關，本案一行都不該碰到 `lib/futures.ts` 的解析解。
- ❌ **不引任何行情套件、不開 WebSocket、不做自動輪詢**。維持「按下真實同步才抓一次」——這頁不是看盤軟體，背景輪詢只會替期交所增加負擔並讓數字在使用者沒看的時候跳動。
- ❌ **不用 MIS 取代每日檔**。月份清單與結算價只有每日檔有（§1.1、§1.4）。
- ❌ **不碰 Python engine**。期貨頁與再平衡頁是本機 gateway（無 engine）唯一還能用的兩頁，掛上 engine 等於讓本機的「真實同步」直接壞掉（同 opt27 §(c)）。
- 📌 **結算價 ≠ 最後成交價，這個差別要留在頁面上**。期交所每日的保證金計算是用**結算價**，不是最後成交價。本案讓頁面改用最後成交價來評價權益數，是為了對齊「期貨商盤中看到的未沖銷部位損益」——這是對的，但**每日結算的官方數字仍以結算價為準**，所以 `settlement` 欄位不要移除，遠月與收盤後的顯示也要看得出來用的是哪一個。
- 📌 **「真實同步」的涵蓋範圍沒有變**：仍然**不會**登入期貨商抓部位與保證金專戶餘額（券商沒有期貨帳戶 API，見 opt23）。按鈕旁那三處說明（常駐一行、`title`、「整體邏輯」分頁）**不要因為這次加了即時報價就順手改弱**——同名按鈕被誤會成「按了就對帳完成」是會影響下單決策的誤會。
- 📌 MIS 的請求量：一次同步 ＝ 一個 POST（所有月份 × 兩時段批次），加上 20 秒快取。這個量級與 opt27 打 TWSE MIS 相當，屬於正常看盤網頁的使用強度。
