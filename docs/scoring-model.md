# 多因子評分模型（定案）— 方案 C：雙引擎分離

> 定案 2026-06-13（階段 1）。取代已作廢的「七維度」。
> 結構由使用者於階段 1 選定為**方案 C：波段引擎 / 當沖引擎各一套分數與邏輯**。
> 全局見 `ROADMAP.md`；輸出型別見 `contracts/`。

## 0. 設計原則（不可違反）

1. **權重是「初始值」，不寫死**：所有權重集中在設定，階段 3 用回測做網格 / 最佳化調整。本檔權重為 v0 起點。
2. **雙引擎分離**：波段（swing，可回測）與當沖（daytrade，live-only）各自獨立計分，互不污染。
3. **可回測 vs live-only 嚴格分流**：富果 Fugle 盤口無歷史，**盤口因子只進當沖引擎、不進回測**。每個因子在 `FactorScore` 標 `live_only`。
4. **無未來函數**：所有可回測因子只能用「當日收盤前已知」資訊；回測嚴禁 look-ahead。
5. **資料缺漏要降信心不要亂補**：因子算不出來時 `confidence` 下降、必要時該因子退出加權並重新正規化，不可用預設值硬填。

## 1. 波段引擎（swing）— 可回測

中期持有訊號。核心分由三因子加權，再乘上大盤環境閘門。

### 1.1 核心分

```
core_swing = 0.40·F_technical + 0.40·F_chips + 0.20·F_sentiment      # 各因子 0~100
```

| 因子 key | 名稱 | 數據源 | 初始權重 | live_only |
|---|---|---|---|---|
| `technical` | 技術面 | FinMind 日 OHLCV | 0.40 | 否 |
| `chips` | 籌碼面 | FinMind 三大法人 / 融資融券 | 0.40 | 否 |
| `sentiment` | 消息情緒面 | 新聞情緒 + **老王報告解析**（`engine/app/puhui` 讀 `reports/**/*.md`，階段4） | 0.20 | 否 |

#### F_technical（子訊號 → 0~100）
| 子訊號 | 計算 | 數據 |
|---|---|---|
| MA 多頭排列 | 5>10>20>60 排列程度（站上幾條、斜率） | OHLCV |
| 乖離率 BIAS20 | `(close-MA20)/MA20`；適度正乖離加分，過熱（>門檻）扣分 | OHLCV |
| 量能 | 量 / 5 日均量；量增配合上漲加分，量增下跌扣分 | OHLCV |
| RSI(14) | 50~70 動能區加分，>80 過熱扣分，自超賣翻揚加分 | OHLCV |
| 三陽開泰 | 連 3 根收紅（收>開）型態 | OHLCV |

#### F_chips（子訊號 → 0~100）
| 子訊號 | 計算 | 數據 |
|---|---|---|
| 三大法人連買 | 外資/投信/自營連續淨買超天數與金額（佔股本比） | FinMind 法人買賣超 |
| 投信認養 | 投信連買（中小型股權重較高） | FinMind |
| 融資增減 | 融資減 + 股價穩 = 籌碼乾淨（加分）；融資暴增追高（扣分） | FinMind 融資融券 |
| 券資比 / 軋空 | 高券資比 + 法人買 = 軋空題材加分 | FinMind |

#### F_sentiment（子訊號 → 0~100）
| 子訊號 | 計算 | 數據 |
|---|---|---|
| 新聞情緒 | 個股新聞情緒分數 −1..+1 → 映射 0~100 | 階段2 已接 `/data/news`（鉅亨/Google）；階段3 做輕量關鍵字/詞典極性 |
| 老王訊號 | 報告個股 emoji 色碼（**🔴看多/🟢看空，語意與股市相反**）＋操作建議關鍵詞 → `signal/score` | **階段4：`engine/app/puhui` 解析 `reports/**/*.md`**（見 `blend-rules.md`） |

> ⚠️ **修正**：舊版這裡寫的老王來源 `data/puhui_analysis/*.json` **從未存在**。
> 階段4 改由確定性解析器（`app.puhui.repo.get_stock_score`）供應 `puhui` 子訊號；
> 當日未提及/報告過舊（超 fallback 視窗）→ 子訊號退出加權、對 news 重正規化、降信心。**仍 live_only、不進回測。**

### 1.2 大盤環境閘門（regime gate）

環境**不進核心分**，而是當乘數，避免逆風接刀：

```
swing_score = clamp( core_swing · gate , 0 , 100 )
gate ∈ [0.5 , 1.1]
```

| regime label | gate | 判定（綜合下列） |
|---|---|---|
| `risk_off` | 0.5 ~ 0.8 | 大盤跌破 MA60、漲跌家數明顯偏空、恐懼貪婪 proxy 偏恐慌、美股隔夜大跌 |
| `neutral` | 0.9 ~ 1.0 | 中性 |
| `risk_on` | 1.0 ~ 1.1 | 大盤站上 MA60 多頭、漲跌家數偏多、情緒偏貪婪 |

環境輸入（階段2 已備源）：加權指數/0050 趨勢（FinMind `/data/ohlcv`）、**TAIFEX 三大法人期貨未平倉（外資淨多空）＋ P/C ratio**（`/data/futures`）、**FRED 殖利率倒掛 `yield_curve`／`vix`**（`/data/macro`，需 key）、美股四大/費半/VIX 隔夜（yfinance `/data/market`）、恐懼貪婪 proxy（融資增減＋VIX＋期貨未平倉方向）。
> ⚠️ **漲跌家數 A/D 無乾淨單一 dataset**（見 `data-layer §10`）→ 階段3 以 proxy（外資期貨淨未平倉方向／P/C／VIX／融資）替代，**不可假設有乾淨 A/D**，並在 regime 輸出標註用 proxy。

### 1.3 波段 action 對映（初始門檻，回測可調）
| swing_score | action |
|---|---|
| ≥ 75 | `buy` |
| 60 ~ 75 | `add` / `watch` |
| 45 ~ 60 | `hold` |
| < 45（持有中） | `reduce` / `sell` |

## 2. 當沖引擎（daytrade）— live-only，不回測

盤中即時訊號，吃富果盤口。輸出「當沖機率」`daytrade_prob ∈ [0,1]`。

```
core_day = 0.45·F_orderbook + 0.35·F_intraday_tech + 0.20·F_market_today   # 各 0~100
daytrade_prob = sigmoid 映射(core_day) ，再經「籌碼過濾」gate（0 或 1）
```

| 因子 key | 名稱 | 數據源 | 初始權重 | live_only |
|---|---|---|---|---|
| `orderbook` | 盤口/主力 | 富果 Fugle 五檔 + 內外盤 + 大單 | 0.45 | **是** |
| `intraday_tech` | 當日技術 | 富果 分K / 開盤強弱 / 量比 | 0.35 | **是** |
| `market_today` | 大盤當日 | 漲跌家數 + 指數即時強弱 | 0.20 | **是** |

#### F_orderbook
| 子訊號 | 計算 |
|---|---|
| 內外盤比 | 外盤成交 / 內盤成交，>1 買方主動 |
| 五檔委買賣力道 | 委買量 vs 委賣量失衡 |
| 大單流向 | 大單淨流入（主力進出） |

#### F_intraday_tech
| 子訊號 | 計算 |
|---|---|
| 開盤強弱 | 開高/開低、相對昨收與大盤 |
| 量比 | 當下累計量 / 同時段歷史均量 |
| 分K 動能 | 1/5 分K 連續方向、突破當日高 |

#### 籌碼過濾（gate，不計分）
籌碼面（法人/融資券）在當沖引擎**只當「能不能當沖」的過濾條件**（流動性、是否處置股、是否爆量過、券源），通過才出當沖訊號，不進加權分數。

### 2.1 為何不回測
富果 Fugle **歷史盤口/tick 拿不到**，當沖三因子皆 `live_only`。當沖引擎只在盤中即時運作；回測模組（階段 3）只跑波段引擎。

## 3. 觀察清單排序（watchlist）

watchlist 自動帶入老王 `mentioned_stocks`（+ 引擎自選），對每檔同時算兩分數、各自排序：

- `swing_score`（波段潛力）→ `rank_swing`
- `daytrade_prob`（短線當沖機率）→ `rank_daytrade`

輸出型別見 `contracts/Watchlist.md`、`contracts/DailySnapshot.md`。

## 4. 權重調整機制（不寫死）

| 項目 | 階段 1（本檔 v0） | 之後 |
|---|---|---|
| 因子權重 | 上表初始值 | 階段 3 回測網格 / 最佳化 |
| 環境 gate 區間 | 0.5~1.1 | 階段 3 用回測驗證並校準 |
| action 門檻 | 第 1.3 節初始值 | 階段 3 依勝率/回撤調 |
| 當沖 sigmoid / 過濾條件 | 佔位 | 階段 3~4 用實盤盤中資料校準 |

實作上權重存在 `engine/app/factors/` 的設定物件（或設定檔），回測輸出最佳權重後回填；**禁止把權重散落在計算邏輯裡**。
