# 寶石排序輔助器

自動看懂「寶石歸位」小遊戲的畫面、規劃每一步、（開啟自動時）自己點滑鼠，過關後連闖到下一關。
沿用水果 2048、永夜迷城輔助器的做法：**範圍優先**（你先框選模擬器畫面，只辨識框內）、
面板停螢幕右邊、自動操控預設關閉、F8 緊急停止、認不得就停手不亂點。

## 怎麼用

1. 桌面捷徑「寶石排序輔助器」（或 `python app.py`）。面板會停在螢幕右邊，模擬器留在左邊。
2. **① 框選畫面範圍**：拖曳框出模擬器裡的遊戲畫面（整個寶石盤面在框裡就好，多包一點邊、
   連左邊道具欄一起框都沒關係）。框到模擬器視窗會自動鎖定視窗，之後搬動視窗不用重框
   （改變視窗大小要重框）。
3. **先別開自動**，看預覽圖：每顆寶石上的色點是程式讀到的顏色，紅圈＝要點的來源管、
   綠圈＝目標管，黃線連起來。面板上方寫著這一步跟「預計還要幾步」。確認色點跟畫面上的寶石
   對得上、建議的一步合理，再開自動。
4. **▶ 開始自動**：程式一步一步點。過關後自動點「獎勵畫面空白處 → 結算畫面『下一關』」連闖，
   遇到認不得的畫面就停手。**F8 隨時停止**（不用切回面板）。
5. 「連闖上限」：0＝不限。**「下一關」每關花 1 顆鑽石**，想控制花費就設個數字，到了會停手等你。

## 遊戲規則（使用者確認 + 1-2 關通關截圖逐步重建驗證）

- 每根管容量 4；搬到「空管」或「頂端同色」的管子。
- 點來源管：頂端連續同色的**整串一起搬**，算 1 步（1-2 關 15 步的重建完全吻合結算畫面的 15）。
  目標放不下整串就不能搬（`Config.partial` 可改成「能放幾顆放幾顆」，實測若發現不對再切）。
- 4 顆同色湊齊 → 合成上鎖（4 顆仍留在管內，管頂多一圈光環），管子不能再動。每合成一組解鎖 1 個藍罐。
- **固定管**（粉色底座＋光環）：裡面的拿不出來、只能放進去（只收同色）。
- **藍罐**（淡藍霜凍，底部有鎖頭）：解鎖前不能動；鎖頭底下那顆看不見。
- **黑色問號寶石**：上方寶石都移開才顯現。
- **鎖球空管**（金色管、中間一顆白色鎖球）：只有道具「解鎖空匣」能開，一律當它不存在。
- 每種顏色的總數是 4 的倍數（1-2 關每色剛好 4 顆；2-1 有的顏色 8 顆）。
- **不使用任何道具**（撤銷、重置關卡、一鍵通關、解鎖空匣）。卡死就停手並回報。

## 原理（想改東西前先看）

**看畫面（vision.py）**

- **找管子**：每根管子有兩道又細又長的亮線（管壁，長度≈管寬 2.2 倍）。找「垂直方向連續很長的
  高亮度線」→ 配對成管子。管子數量、幾排、畫面縮放多少都不影響（1-2 關 5+5 根、1-3 關 4+3 根、
  2-1 關 7+7 根用同一套）。結果不整齊（偏亮/偏暗/模糊）會自動換幾組門檻重試，取最像的。
- **管子種類**看管壁顏色：金＝一般、粉白＝固定、淡藍＝藍罐。
- **格子**：所有幾何量都以「管寬」為單位（格距 0.64、最底格離管壁下端 0.53），取樣小塊判斷
  空／寶石／問號（黑）／鎖球（亮白圓）。
- **顏色**：用色相直方圖的**峰值**估計（`robust_hue`），對照 `DEFAULT_PALETTE` 的色相中心。
  不用平均色相——寶石切面很多，平均會隨亮度門檻飄移（實測綠色在亮度 -8% 時 112°→129°，
  被當成別種顏色）；峰值法同條件下飄移 < 6°。藍罐裡有霜的寶石放寬容許值。
  沒見過的顏色會自動開新項目（名稱 `h<色相>`），只有盤面通過所有檢查、連續穩定才寫進
  `palette.json`，避免轉場髒畫面把假顏色永久寫進去。
- **過關畫面**：兩段——①「挑戰成功／恭喜」＋獎勵，底下三顆按鈕是**暗的**（點空白處繼續）；
  ②結算，三顆按鈕**亮**（藍「返回」、黃「分享」、黃「下一關」）。用「暗紅背景＋底部一排藍黃黃按鈕」
  加按鈕亮度判斷，不吃固定座標。

**規劃（solver.py）**

- 加權 A*（找得到解就好，不追求最少步）＋「湊滿一組／搬進固定管」必然有利的一步強制優先。
- **看不見的寶石**（問號、鎖頭底下）：每色缺幾顆才湊成 4 的倍數 → 推算它們可能是什麼，
  抽幾種「真相」各解一次，第一步用投票決定（`plan()`）。
- **`Planner` 有記憶**：選好一個世界的完整解後，只要畫面跟計畫預期的一致就照著走，
  只有新資訊（問號顯現成不同顏色、藍罐解鎖順序不同、走出計畫外）才重規劃。
  **原因**：每步重新抽樣時，第 N 步選的搬法第 N+1 步會被改成搬回去（2-1 關實測來回打轉）。
- 藍罐誰先解鎖不知道 → 抽樣時一半的世界用「由左到右」、一半用「反向」，第一步不押注在沒驗證的順序上。

**執行（engine.py）**

- 每一步：擷取 → 辨識 → 穩定確認（連續兩次讀到一樣）→ 寶石總數守恆檢查 → 規劃 → 點來源管 →
  點目標管 → 等動畫 → 驗收（盤面真的變成預期的樣子）。
- 走完一步一定驗收：沒變 → 重試 1 次，仍沒變 → 列入黑名單改走別的（盤面一變黑名單就作廢）；
  預期外的變化 → 從新盤面重新規劃；連續 3 步沒反應 → 停手。
- 「預測」用 `predict_cells`、比對用 `compatible`（預測裡看不見的格子，實際變成什麼都算對）。
- 過關後：獎勵畫面點空白處 → 結算畫面點「下一關」→ 新的一關（換關時清掉這一關所有暫存）。
- 停手條件（一律說明原因，不硬猜）：認不得畫面 60 秒、盤面讀不準 12 秒、寶石總數一直對不上、
  找不到解、點擊目標被別的視窗蓋住（LoL/Chrome 全螢幕內容常會）、視窗縮小或大小變了、
  過關畫面連點 4 次沒反應（鑽石不夠也會這樣）、F8。
- 停手時把畫面存進 `debug/`（最多留 30 張）方便事後對照。

## 檔案

| 檔案 | 用途 |
|---|---|
| `app.py` | 置頂面板、框選遮罩、預覽 |
| `engine.py` | 範圍追蹤、設定、主迴圈、驗收、連闖 |
| `vision.py` | 擷取、管子偵測、格子讀取、色盤、過關畫面 |
| `solver.py` | 規則、搜尋、世界抽樣、`Planner` |
| `render.py` | 預覽圖繪製（只用 PIL，可存成 PNG 檢查） |
| `control.py` | SendInput 點擊、視窗查詢（從永夜迷城移植，已在真 BlueStacks 驗證） |
| `simgame.py` | 遊戲模擬器（測試用） |
| `tools/launch.ps1` | 桌面捷徑指向的啟動腳本（**UTF-8 with BOM**） |
| `testdata/` | 使用者給的真實截圖（測資，別指向暫存區，會被覆蓋） |
| `config.json` / `palette.json` / `debug/` | 使用者本機資料（已 gitignore） |

## 測試

四組都是純離線（不開可見視窗、不碰桌面、不送真點擊）：

    python test_vision.py    # 真實截圖逐格核對盤面、畫面分類、抗干擾（雜訊/亮度/模糊/縮放）
    python test_solver.py    # 規則、使用者實際玩的 15 步、2-1 多種真相端到端
    python test_engine.py    # 模擬遊戲＋假時鐘：連闖、點擊被吃掉、停手條件、真實截圖的點擊座標
    python test_app.py       # 面板（視窗建立後隱藏）

資料夾用環境變數 `GEMSORT_DATA_DIR` 導到暫存夾——測試不能碰使用者真正的 config/palette。

## 維護筆記（都是真的踩到或量到的）

- `tools/launch.ps1` 必須存成 **UTF-8 with BOM**（捷徑跑的是 PowerShell 5.1，無 BOM 會把中文當 Big5 讀）。
  啟動子行程要明寫 `-WindowStyle Normal`。
- Tk 物件只准在主執行緒回收（`gc.disable()` + `_pump` 手動 `gc.collect()`），否則背景偵測執行緒
  觸發循環 GC 會在錯的執行緒呼叫 Tcl 而死結。
- 模擬器的合成規則：一根管湊滿 4 顆同色時，底下的問號一定會顯現（截圖上合成完的管子全是看得見的
  同色寶石）。`simgame.py` 一開始漏了這條，引擎在最後一根 `[?, 紫, 紫, 紫]` 卡死，是模擬器的錯不是求解器。
- 黑名單只針對「當時那個盤面」：成功走了別步就要清掉，不然後面需要那一步時被誤禁、變成「找不到解」。
- 顏色認錯會被數量檢查抓到（每色總數要是 4 的倍數）→ 面板說「顏色數量對不上」並停手。
  `palette.json` 出現不認識的 `h<數字>` 顏色，多半是髒畫面誤學進去的，刪掉那一項即可。
- 要改色相中心（`DEFAULT_PALETTE`）：用 `robust_hue` 對 `testdata/` 重新量，別憑感覺；
  最近的兩色 ruby(344°) / fire(6°) 只差 21°。

## 已知限制／尚未在真遊戲驗證的事

**沒有在真 BlueStacks 上跑過**（開發時使用者在玩別的遊戲，會開置頂視窗/送真點擊的驗證都延後）。
離線已驗證的是：辨識、規劃、引擎流程、點擊座標對得上真實截圖上的管子與按鈕。還沒驗證的：

1. **遊戲操作方式**：假設「點來源管 → 點目標管」（使用者確認過）。選取後的視覺效果沒看過，
   所以每一步都靠「盤面真的變了」驗收，而不是靠看選取狀態。
2. **點擊位置**：點管身第 2 格中心。空管也點同一個位置（假設整根管子都是點擊範圍）。
3. **搬不下整串**：假設不能搬（`partial=False`）。實測若遊戲會搬一部分，改 `Config.partial`。
4. **藍罐解鎖順序**：多個藍罐時誰先開沒看過（1-2 關只有一個）。規劃已保守處理，實測後可收斂。
5. **問號寶石的顏色跟上面那串同色時**，遊戲會不會把它一起搬（我的模型是「會」，用真實顏色算）。
   模型不對的話最壞是點了沒反應 → 重試 → 黑名單 → 改走別的。
6. **獎勵畫面**點的是按鈕上方空白處；若遊戲要點特定位置才繼續，會停手並提示。
7. 只見過 4 種寶石外觀以外的顏色時（新關卡的新寶石）會自動開新色，但同色相近的兩種（差 < 20°）
   可能混在一起——預覽圖上的色點可以肉眼核對，數量檢查也會抓。
8. 容量固定 4（`vision.CAP`）；其他容量的關卡沒見過。
